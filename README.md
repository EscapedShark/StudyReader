# 学习书架

Mac / iPhone 原生 Markdown 学习阅读器，支持 iOS 17+ 与 macOS 14+，可连接用户选择的 iCloud Drive 资料库。

## 运行

1. 首次打开完整 Xcode，完成许可确认和组件安装。
2. 打开 `StudyReader.xcodeproj`，选择 `StudyReader` scheme。
3. 目标选择 `My Mac` 或可用的 iPhone 模拟器，点击 Run。
4. 真机运行时，在 Signing & Capabilities 里选择自己的 Team，并设置唯一 Bundle Identifier。

Mac 和 iPhone 模拟器的 Debug 配置使用本地签名，无需选择开发团队。iPhone 真机与 Release 配置使用自动签名，需要配置 Team。如果 Xcode 仍显示旧的团队报错，关闭并重新打开工程，确认运行目标是 `My Mac` 或具体模拟器，再按 ⌘R。

已经打包本地 Markdown、公式库、样式和字体，打开工程不需要 npm 或 XcodeGen。首次运行自带概率论样例。

## 当前能力

- 原生双端导航、目录与资料列表。
- Markdown、表格、图片、美元/括号分隔符公式。
- 本地文件与文件夹导入，附件相对路径保留；完全重复导入会跳过。
- 新建空资料夹、重命名资料夹、资料夹和文章拖动排序、文章拖到左侧资料夹移动；名称、归属和顺序自动保存。
- 文章右键删除（iPhone 长按菜单），删除前确认，清理书架副本、收藏和阅读记录。
- 资料夹右键 →「删除资料夹…」（iPhone 长按菜单），确认名称和文章数量后整组删除；支持空资料夹。共享图片保留给其他文章，删除前的外部原文件保留。已连接同步时，资料夹及文章删除也会同步。
- 在“更多”菜单编辑当前文章的 Markdown，保存后立即刷新正文、目录和搜索；取消时保留或放弃草稿。
- 文章按文件名显示（省略 Markdown 扩展名）。右键重命名文件（iPhone 长按菜单），正文和一级标题保持原样，保留收藏、进度、资料夹与图片。
- 标题/正文搜索，显示匹配片段与关键词高亮，点击结果定位到正文匹配段落；收藏、最近阅读、文章目录、页内查找。
- 字号和外观、Mac 页面宽度、答案折叠、文本选择、点击公式复制 LaTeX。
- 阅读位置持久保存；导出当前文章 MD 原文，或把文章／资料夹连附件导出为可重新导入的资料包。
- 连接同一个 iCloud Drive 文件夹，同步文章、图片、文件名称、资料夹、归属、排序、收藏与阅读位置；离线副本、自动检查、冲突副本和断开连接。

默认仍使用本机资料库，连接同步文件夹后才会传送资料。最近阅读与阅读偏好暂不跨设备同步。重新导入修改过的资料会保留成独立副本，不覆盖旧资料。

Mac 阅读设置新增「页面宽度」：标准（840）、加宽（1120）和铺满窗口。全屏时选择「铺满」即可利用正文区域的可用宽度，保留两侧阅读边距。切换立即生效、保留当前阅读位置，并记住选择；iPhone 沿用原有布局。

搜索时，单篇文件缺失、编码错误或暂时不可读不会中断其他文章。结果上方显示无法搜索的篇数，点击可查看文件名、路径和原因；恢复文件后可直接「重新搜索」。每篇显示首处正文匹配的片段；仅标题命中时标注「标题匹配」。点击正文结果会展开所在的折叠答案，并高亮对应段落中的关键词；在 LaTeX 原文或链接目标中命中时标出所在内容块。重复段落按源文位置区分。输入关键词本身不更改阅读进度，实际点击跳转后按正常阅读保存。

“导出本文 Markdown”只输出原文；“导出本文及附件”以及资料夹右键／长按菜单里的“导出资料夹及附件”输出普通资料文件夹，含原始 MD、本地图片和文章顺序清单。通过“导入资料文件夹／资料包”选择导出的文件夹即可恢复内容、名称和组内顺序，空资料夹也支持。不同来源的同名附件隔离存放，Markdown 字节和相对图片路径不变；为保留可能共享的图片，会包含所选文章所在导入包的全部图片。资料包总量不超过 200 MB，与导入限制一致；它不包含阅读记录和偏好。

## 在 Mac 和 iPhone 之间同步

1. 两台设备登录同一个 Apple 账号，开启 iCloud Drive，并安装此次更新后的 App。
2. 在 Mac 的 Finder → iCloud Drive 中创建一个空文件夹，例如「StudyReader 资料库」。
3. 在 Mac App 点击侧栏底部「设置 iCloud Drive 同步」（或「＋ → 资料库同步」），选择「新建同步资料库」，选中这个空文件夹。现有资料会加入其中，连接前自动保留本机备份。
4. 等待该文件夹出现在 iPhone「文件」→ iCloud Drive 中。在 iPhone App 打开同一设置，选择「连接已有资料库」，选中相同文件夹。已有资料会合并，相同的导入包内容按稳定映射去重。
5. 以后直接在任一端 App 中导入、编辑、改名和整理。打开 App 时、资料夹变化时和前台每 20 秒自动检查，也可以按「立即同步」。

收藏和取消收藏现在也会同步，两端都需更新到支持收藏同步的版本。离线取消收藏会保留取消记录，旧设备重连不会让它重新出现。旧版本的本机收藏会自动迁移，迁移不覆盖更新的取消操作。

两端更新到支持阅读进度的版本后，使用原来的同步连接即可，不需要重新导入。滚动暂停约 3 秒后会尝试同步位置；另一端收到后，重新打开文章即可接着读。如果文章已经打开，会出现「另一台设备更新了阅读位置」提示，按「接着读」跳转，按「忽略」继续当前阅读。同步采用最后一次实际阅读位置，主动向前翻或回到开头也会保存。仅打开文章、调整字号或接收远端进度不会产生新的阅读时间。不同屏幕优先按原文段落和段内位置恢复。

这是用户选定的共享文件夹，不使用应用专用 iCloud 容器或 CloudKit，不需在工程中配置 iCloud capability。系统负责 iCloud 传送，文件写入后显示「等待 iCloud 上传」不代表另一端已收到；未下载完时保留当前本机资料，后续重试。已下载内容可离线阅读和编辑。断开连接保留本机资料，不删除共享文件夹。

并发修改同一文章时保留「冲突副本」；一端删除、另一端离线编辑时保留编辑版本。资料夹的名称、文章归属和排序分别合并，同一个排序同时修改时使用确定的版本顺序。连接前备份位于本机 StudyReader 数据目录的 `Backups/BeforeSync-<UUID>/`。格式、恢复机制与待验收项见 [SYNC.md](SYNC.md)。

单篇 MD 限制 5 MB、单张图片 25 MB、每批导入 200 MB。远程图片不会自动下载；请导入本地附件。HTML 原文与脚本不执行。

全文搜索把扫描分给多个核，沿用本地化匹配，并忽略正文中不显示的 YAML 头；不会用上一次的结果收窄范围（含连字的正文会回答「confi」却不回答「conf」，收窄会静默丢结果）。导入的图片按文件头记下像素尺寸，正文加载时先占好方框，不再上下跳动，也不必等图片解码就能恢复阅读位置。阅读状态的编码和写盘都在后台队列完成。公式额外输出的那份 1px MathML 副本只在 VoiceOver 或切换控制开启时渲染，超长公式文章的首次布局少三分之一，页面总高和滚动都不受影响。

阅读时记录位置只测量阅读线附近的段落，不再每次从文章开头扫描整篇；正文摘要按段落缓存，位置没有变化时不再通知 App，书架进度条的刷新限速到每 0.5 秒一次。iPhone 的阅读视图不透明，正文一直铺到屏幕底端，最后几行避开主屏幕指示条；书架底部出现导入或提示条时会重新让出这段位置。宽表格、代码块和宽公式横向滑到尽头不再带动整页。

资料库启动时在后台读取目录清单，点开文章后才读取正文。全文搜索在后台执行，输入停顿 200 ms 后开始查询，连续输入会取消旧查询；最近 8 个完整结果的片段和位置可复用，不保留整篇正文。部分文件失败时不缓存这一轮结果，让重试能重新检查文件。收藏、阅读进度和资料夹移动不会触发全文重查。新导入的资料增量加入书架，重复导入不再重读整库。

阅读状态保存采用变化标记：没有变化时不编码、不写盘；需要持久化时异步等待后台写入，主线程继续响应。并发保存保持快照顺序，失败后保留待保存状态，后续可重试。iPhone 进入后台时为本机保存申请短暂执行时间，Mac 正常退出前等待保存完成。

WebKit 内容进程退出时，阅读器会自动重新加载当前文章、字号、外观和最近收到的阅读位置。恢复使用新会话隔离旧回调，不产生新的阅读时间；一分钟内连续退出超过三次时暂停自动重试，提示手动重新加载。

原文与排版分别使用有容量上限的缓存；超大文章仍可阅读，但不会挤占缓存。详细测量、限制与复测方法见 [PERFORMANCE.md](PERFORMANCE.md)。

## 整理资料（Mac）

1. 点击工具栏的“新建资料夹”，或按 ⇧⌘N，输入名称后创建。空资料夹在重启后仍然保留。
2. 按住文章标题或行内空白处上下拖动，在插入线处松开即可排序；也可以右键文章，选择“上移”或“下移”。
3. 把文章拖到左侧目标资料夹，资料夹高亮后松开即可移动；右键“移到资料夹”也可完成相同操作。
4. 选中资料夹后，用“＋ → 导入 Markdown 到当前资料夹”直接添加文章。“导入资料文件夹”仍创建独立资料夹。
5. 右键文章 →“删除文章…”，确认后从所有列表中删除。原始导入文件与其他文章使用的图片保留；重启后不会重新出现，之后可重新导入。
6. 文章右上角“更多（…）”→“编辑当前文章”，修改 Markdown 后点“保存”，或按 ⌘S。取消时若有未保存内容，会询问是否放弃。写入失败时保留编辑草稿并显示错误。
7. 右键文章 →“重命名…”，输入文件名后保存。实际修改资料库副本的文件名，保留原来的 `.md` / `.markdown` 扩展名和所在目录；正文、一级标题与图片不变。同一导入目录内的同名文件会提示冲突，不会覆盖；不同目录中的同名文章可以并存。
8. 右键左侧资料夹 →“重命名…”，修改预填的名称后保存。空资料夹也支持，名称重启后保留；文章归属、顺序、收藏和阅读进度保持不变。空名称、超过 100 字、控制字符及与其他资料夹重名时会提示错误。iPhone 长按资料夹使用同一入口。
9. 按住左侧资料夹名称上下拖动，在插入线处松开，或右键选择“上移”“下移”。iPhone 点击“资料夹排序”，拖动行尾手柄，完成后点击“完成排序”。“全部资料”“最近阅读”和“收藏”固定在顶部，空资料夹可参与排序。

编辑与重命名只修改资料库中的副本。书架名称统一取文件名，省略 Markdown 扩展名，独立于正文中的标题。编辑正文不会改名，重命名也不会改正文。旧版本缓存的一级标题或别名会在下次启动时按已有文件路径校正，文档 ID、正文和阅读记录保留；这个迁移只读取清单，不读取正文。打开多个窗口时，过期的编辑或重命名不会覆盖另一窗口已保存的修改。正文和清单使用原子写入；清单写入失败会恢复原文件或原文件名。

资料夹顺序保存在整理记录中，不再随名称自动重排。旧资料首次升级时保留之前看到的字母排序，之后以手动顺序为准；新建资料夹追加到末尾，重命名保持原位置。资料夹排序和文章移动使用不同的拖放类型，不会把资料夹误当成文章移动。

切换文章或进入空栏目之前，先等待阅读器保存当前位置，再变更选择。离开后暂停滚动上报，避免隐藏页面的布局变化覆盖进度；新栏目仍包含当前文章时保留当前选择。恢复位置优先匹配同一源文本块与文字，重复的“题目”“解答”不再匹配到前面第一处。每次显示使用独立会话标识，迟到的旧页面消息不会覆盖新位置。主动回到文章顶部仍可正常保存为 0%。

Mac 与 iPhone 图标使用 `Assets.xcassets/AppIcon.appiconset`。Mac 版保留蓝色圆角图标，外部使用透明背景；iPhone 版使用蓝色铺满的正方形底图，由系统处理圆角。Mac 启动时直接加载包内的 `AppIcon.icns` 更新 Dock 图标，避免 Xcode 在同一路径反复运行时沿用旧的通用图标。

文章行只显示标题、收藏和阅读进度，不再显示标题下方的资料夹名称。Mac 的文章与资料夹列表采用原生 `NSTableView` 拖放回调，统一处理开始拖动、插入线、资料夹高亮与落下后的保存；拖放数据类型已在 App 的 Info.plist 声明。更新工程后应停止旧进程并重新 Run，以加载新的控件和类型注册。

实现接口依据：[Apple 的表格拖动源接口](https://developer.apple.com/documentation/appkit/nstableviewdatasource/tableview(_:pasteboardwriterforrow:))、[Apple 的拖放与自定义数据类型说明](https://developer.apple.com/documentation/swiftui/adopting-drag-and-drop-using-swiftui)。

“全部资料”和各资料夹分别保存手动顺序；收藏沿用“全部资料”的顺序。搜索结果中的排序只调整可见文章，隐藏文章保留原位置。“最近阅读”始终按阅读时间排列，可以从中拖出文章移动到资料夹。

资料夹是书架内的整理分组。移动只更新文章归属，MD 与附件的相对目录保持不变，避免相对图片路径和同名附件冲突；文档 ID、收藏、阅读进度保持不变。旧资料首次打开时自动生成整理记录，不需要重新导入。整理记录保存在 App 的 `library-organization.json` 中，写入成功后才更新界面。

## 修改渲染组件

```sh
npm ci --ignore-scripts
npm run build
npm test
```

编辑 `WebReader/` 后运行构建。生成的离线资源保存在 `StudyReader/Resources/Reader/`，包含第三方许可。

工程描述在 `project.yml`。添加/移除 Swift 文件后可以用 XcodeGen 2.46.0 重新生成工程：

```sh
xcodegen generate
```

本次开发用的 XcodeGen 位于忽略提交的 `.tools/xcodegen/bin/xcodegen`；也可以在 Xcode 中直接添加文件。
